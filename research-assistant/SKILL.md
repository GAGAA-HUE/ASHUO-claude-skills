# Research Assistant - 智能信息搜集与验证助手

## 核心能力

1. **深度多源搜索** — 并行搜索多个角度，获取全面信息
2. **交叉验证引擎** — 多源确认、权威评分、时效优先、矛盾检测
3. **定时监控任务** — 周期性自动搜集指定主题的最新信息
4. **结构化报告** — Markdown + HTML双格式，清晰标注来源和可信度
5. **每日简报推送** — 自动生成前一天关键新闻摘要

---

## 使用方式

### 即时搜索模式

用户输入搜索请求，执行完整搜集-验证-报告流程：

```
用户: "搜集关于AI Agent最新发展的资料"
用户: "验证'某明星结婚'这个消息"
用户: "查一下新能源汽车2024年销量数据"
```

### 定时监控模式

用户设置周期性信息搜集任务：

```
用户: "每周一早上9点给我搜集AI领域最新动态"
用户: "每天下午6点监控某股票价格变化"
```

## 执行流程

### 阶段一：意图解析与策略制定

1. **解析用户请求类型**
   - `即时搜索` — 一次性深度搜集
   - `定时监控` — 周期性任务设置
   - `验证查询` — 针对特定信息的真伪验证

2. **制定搜索策略**
   - 提取核心关键词
   - 确定需要搜索的角度（新闻/学术/社交媒体/官方来源）
   - 规划验证维度优先级

### 阶段二：并行深度搜索

**启动多个子代理并行搜索不同维度：**

| 代理 | 职责 | 搜索重点 |
|------|------|----------|
| 新闻代理 | 最新动态 | 新闻网站、行业媒体 |
| 学术代理 | 深度分析 | 论文、研究报告 |
| 社交代理 | 舆论风向 | 社交媒体、论坛讨论 |
| 官方代理 | 权威数据 | 政府/企业官方发布 |

**每个代理执行：**
1. 使用 WebSearch 进行多关键词搜索
2. 使用 WebFetch 获取高相关性页面内容
3. 提取关键信息点和来源元数据
4. 初步评估来源可信度

### 阶段三：交叉验证引擎

**1. 多源确认 (Multi-Source Confirmation)**
- 同一事实需在 ≥3 个独立来源中出现
- 标记仅出现1-2次的信息为"待验证"
- 记录每个事实的来源列表

**2. 权威评分 (Authority Scoring)**

| 来源类型 | 基础权重 | 示例 |
|----------|----------|------|
| 政府机构/官方数据 | 1.0 | gov.cn, 统计局 |
| 顶级期刊/学术机构 | 0.9 | Nature, Science |
| 权威媒体 | 0.8 | 新华社, Reuters |
| 行业媒体 | 0.7 | TechCrunch, 36氪 |
| 自媒体/博客 | 0.4 | 个人公众号 |
| 匿名论坛 | 0.2 | 贴吧, 部分Reddit |

**计算公式：**
```
可信度得分 = Σ(来源权重 × 时效系数) / 来源数量
```

**3. 时效优先 (Recency Priority)**
- 新闻类：48小时内为"最新"，一周内为"近期"
- 数据类：季度内为"最新"，一年内为"有效"
- 研究类：3年内为"前沿"，5年内为"有效"

**时效系数：**
- 最新/前沿：1.0
- 近期/有效：0.8
- 较旧：0.5
- 过时：0.2

**4. 矛盾检测 (Contradiction Detection)**
- 对比不同来源对同一事实的陈述
- 标记数值差异 >10% 或定性相反的信息
- 呈现矛盾双方的观点和来源

### 阶段四：结构化报告生成

**支持双格式输出：Markdown（详细分析）+ HTML（美观展示）**

#### Markdown 报告模板

```markdown
# 信息搜集报告：{主题}

> 生成时间：{timestamp}
> 搜索范围：{搜索维度列表}
> 验证状态：✅ 已验证 / ⚠️ 部分待验证 / ❌ 存在争议

---

## 核心发现（高可信度）

| 事实 | 可信度 | 主要来源 | 时效 |
|------|--------|----------|------|
| ... | ⭐⭐⭐⭐⭐ | [来源1], [来源2], [来源3] | 最新 |

---

## 详细信息
...
```

#### HTML 报告特点

- **响应式设计** — 适配手机和桌面端
- **视觉层次清晰** — 渐变头部、卡片式布局
- **通俗解释框** — 每个复杂概念配大白话说明
- **数据可视化** — 表格、标签、高亮框

**HTML 报告保存路径**：`c:\Users\vip\.claude\{主题}\report_YYYY-MM-DD.html`

---

### 阶段五：每日简报模式

当用户要求"每天推送新闻简报"时，执行以下流程：

**1. 简报内容结构**
- 前一天关键新闻（5-7条）
- 按重要性排序
- 每条包含：标题、一句话摘要、可信度、通俗解释
- 简要国际形势分析（20%）

**2. 输出格式**
- 自动生成 HTML 页面
- 保存到 `c:\Users\vip\.claude\daily_{主题}\`
- 文件名：`{主题}_news_YYYY-MM-DD.html`

**3. 定时任务设置示例**

```python
# 用户：每天早上10点推送AI新闻简报
CronCreate(
  cron="0 10 * * *",
  prompt="执行research-assistant skill，查询前一天AI领域关键新闻，生成简报（5-7条核心新闻+20%国际形势分析），输出HTML页面",
  durable=True
)
```

---

### 阶段六：定时任务设置（通用）

如果用户请求包含定时需求：

1. **解析时间表达式**
   - "每天早上9点" → `0 9 * * *`
   - "每周一" → `0 9 * * 1`
   - "每小时" → `0 * * * *`

2. **创建 Cron 任务**
   ```python
   CronCreate(
     cron="{解析后的cron表达式}",
     prompt="执行research-assistant skill搜索'{主题}'并生成报告",
     durable=True  # 持久化保存
   )
   ```

3. **任务管理**
   - 记录任务ID和配置
   - 提供任务列表查询功能
   - 支持任务删除/修改

## 输出规范

### 可信度评级

| 评级 | 分数 | 含义 |
|------|------|------|
| ⭐⭐⭐⭐⭐ | ≥0.9 | 高度可信，多权威来源确认 |
| ⭐⭐⭐⭐ | 0.7-0.89 | 可信，有权威来源支持 |
| ⭐⭐⭐ | 0.5-0.69 | 一般可信，来源有限 |
| ⭐⭐ | 0.3-0.49 | 可信度低，需进一步验证 |
| ⭐ | <0.3 | 不可信或来源可疑 |

### 时效标签

- 🟢 最新 — 新闻48h内/数据本季度
- 🟡 近期 — 新闻一周内/数据半年内
- 🟠 较旧 — 新闻一月内/数据一年内
- 🔴 过时 — 超过上述时间

---

## 边界与限制

1. **不处理**
   - 需要登录才能访问的内容
   - 付费墙后的学术论文（除非用户提供）
   - 实时性要求极高的数据（如毫秒级股价）

2. **明确告知用户**
   - 搜索结果受限于搜索引擎索引范围
   - 交叉验证不能100%保证事实准确性
   - 建议对关键决策进行二次核实
