# 步骤 1：亮点设计流程

## 任务

从候选热点或长青选题中，通过三步转化法，产出一个可执行的"衍生选题转化结果"。

## 输入

- 用户提供的候选选题（平台热点 / 长青题材 / 跨域挪用）
- LLM 主动提议的候选选题（基于来源权重）

## 执行步骤

### 1. 收集候选选题

读取 `rules/topic-transformation.md` 中的来源权重和三步转化法。

如果用户没有提供候选选题，LLM 主动提议 3 个候选选题（基于当前平台热点或长青题材）。

### 2. 三步转化

对每个候选选题，执行三步转化：

**第 1 步：识别核心吸引力**
- 抽象出 1-2 个情感钩子词（反差 / 紧张 / 奇观 / 利益 / 共鸣）

**第 2 步：保留情感钩子，置换物理载体**
- 将钩子词置换为冰洞场景内的具体看点

**第 3 步：与冰洞原型 L1 强制配对**
- 从 `config/l1-prototypes.md` 中选择最匹配的 L1 原型
- 如果需要派生，从 `rules/l2-derivation.md` 中选择派生规则

### 3. 产出衍生选题转化结果

按以下格式输出：

```
## 衍生选题转化结果

**来源**：[平台热点 / 长青题材 / 跨域挪用] + [具体选题]
**钩子词**：[情感钩子 1, 情感钩子 2]
**翻译后的看点**：[具体描述]
**L1 配对**：[L1-X（原型名）]
**派生规则**：[无 / 杂交 / 变量替换 / 尺度畸变]
**派生来源**：[如果用了派生，标注来源]
```

### 4. 自检

执行 `workflow/quality-checklist.md` 中的"步骤 1 检查点"。

### 5. 等待用户过目

将衍生选题转化结果提交给用户。

- 用户接受 → 进入步骤 2
- 用户打回 → 根据反馈修订，重新执行步骤 2-4
- 用户改 → 按用户意见修订，重新执行步骤 4-5

## 输出

一份"衍生选题转化结果"文档，包含：
- 来源
- 钩子词
- 翻译后的看点
- L1 配对
- 派生规则（如有）
- 派生来源（如有）

## 完成标志

用户明确说"通过"或"OK"或"继续"。
